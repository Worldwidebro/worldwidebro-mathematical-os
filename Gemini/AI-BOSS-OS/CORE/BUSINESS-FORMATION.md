# BUSINESS FORMATION SYSTEM
## The Constitution for the Venture Creation Machine

---

## 1. Purpose

This document defines the core operating law and blueprint for how the enterprise creates, launches, operates, and scales companies. Every AI agent, venture template, and workflow MUST reference this file when executing venture creation tasks.

---

## 2. Entity Hierarchy

The ecosystem organizes companies and products in a strict structural hierarchy:

```text
WinnersCircleWCLLC (Holding Company / Ownership Layer)
│
└── Operating Companies (OPCOs - Sector Specialization Layer)
    │
    └── Ventures (Venture Layer - Individual Startup Entities)
        │
        └── Product Lines (Execution Layer - Specific Value Offerings)
            │
            └── Customers (Attention & Consumption Layer)
```

---

## 3. Formation Pipeline

Every venture undergoes a standardized progression pipeline from idea discovery to market exit:

1. **Idea**: Raw concept discovery, sector gap identification.
2. **Opportunity Analysis**: Initial TAM/SAM/SOM modeling, competitive landscape evaluation.
3. **Market Validation**: RAG checks across Obsidian vaults, Qdrant vectors, and Web/social interest indices.
4. **Business Case**: Formulation of the monetization upgrades plan (v1 Media &rarr; v2 Service &rarr; v3 SaaS).
5. **Approval**: Board governance evaluation and capital allocation clearance (Decision Engine RACI).
6. **Entity Creation**: Legal setup, DBA/EIN registration, treasury bank accounts initialization.
7. **Brand Creation**: Domain acquisition, website branding, content engine setup (Worldwidebro).
8. **Technology Setup**: Git repository creation, database instance provisioning, API Gateway endpoints wiring.
9. **Operations Setup**: SOP checklists initialization, AI agent workforce assignment, n8n workflow deployment.
10. **Launch**: Public announcements, newsletter campaigns, lead generation enrichment.
11. **Scale**: Ongoing optimization, expansion of product lines, scaling token usage.
12. **Exit**: Valuation audits, acquisition, or capital extraction/dividends.

## 4. Company Creation Checklist

Before a company is marked `Active` in the portfolio registry, it must pass the following checks:

### Legal
- [ ] Entity formation registered.
- [ ] EIN/Tax ID obtained.
- [ ] Staged treasury/banking accounts linked.
- [ ] Standard vendor and customer contract templates loaded.
- [ ] Intellectual Property (IP) assignment agreements signed to WinnersCircleWCLLC.

### Technology
- [ ] Git repository initialized on central server.
- [ ] Domain name registered and SSL certificate active.
- [ ] Staging and production cloud environments configured.
- [ ] PostgreSQL database cluster and Redis cache instance created.
- [ ] Security firewalls and Langfuse tracing keys active.

### Operations
- [ ] Standard Operating Procedure (SOP) files compiled.
- [ ] Third-party vendors and API integrations (Medusa, Stripe, Twenty CRM) active.
- [ ] AI Agent Workforce allocated (Chief, Operations, Finance, Dev agents configured).

### Growth
- [ ] Front-end website deployed (VEX bundle).
- [ ] Email newsletters and social accounts configured.
- [ ] Customer feedback channels and support tickets active.
- [ ] CRM pipeline configured inside Twenty CRM.

## 5. Required Documents

Every new company folder created under `/07-VENTURES/` must contain the following core documents:

* **VISION.md**: Generational perspective, long-term strategic direction.
* **MISSION.md**: Target market definition, 3-year objectives, milestones.
* **BUSINESS-MODEL.md**: Pricing tiers, monetization upgrades path, unit economics.
* **PRD.md**: Product Requirements Document for the initial MVP.
* **ARCHITECTURE.md**: Tech stack, database schema diagram, third-party APIs.
* **OPERATIONS.md**: AI Agent workforce layout, workflow diagrams, active SOP registry.
* **MARKETING.md**: Content schedules, lead scraper registries, creator network alignments.
* **FINANCE.md**: Treasury routing setup, budget limits, YTD ledger summaries.
* **LEGAL.md**: EIN, certificates, IP, compliance audits.
* **ROADMAP.md**: 12-month sprint plan, release history.

## 6. Ownership Model

Ownership and equity allocations are structured directly through WinnersCircleWCLLC:

```text
Founder (WinnersCircle / Principal)
   ↓ (100% control)
WinnersCircleWCLLC (Capital & Ownership Pool)
   ↓ (100% control)
Operating Company (OPCO - e.g., Tech OPCO, Healthcare OPCO)
   ↓ (100% or majority equity stake)
Venture (Individual Startups - e.g., HealthGuard AI)
   ↓ (100% ownership)
Product Lines (Underlying assets & APIs)
```

## 7. Funding Stages

Ventures progress through six capital gates:

* **Stage 0: Idea**: Self-funded. Research validation.
* **Stage 1: Validation**: $10,000 allocated for market scraping and landing page testing.
* **Stage 2: MVP**: $50,000 allocated for initial VEX website construction and Medusa API wiring.
* **Stage 3: Revenue**: Venture generates first revenue dollar; achieves organic cash-flow neutrality.
* **Stage 4: Growth**: $250,000 allocated to expand customer CRM pipelines and scale marketing.
* **Stage 5: Scale**: Joint venture partnerships and external capital matching options.
* **Stage 6: Exit**: Sale to larger holdings or public listing.

To maximize efficiency and reuse, every venture inherits the following infrastructure from the IZA OS:

1. **AI Agents**: Centralized LLM gateway routing and common agent templates.
2. **Finance**: Unified Stripe gateways, accounting ledger APIs, and tax modules.
3. **Legal**: Standard operating contracts and compliance checking scripts.
4. **Marketing**: Shared creator network distributions and social automated calendars.
5. **Infrastructure**: LiteLLM routers, Docker orchestrations, PostgreSQL databases.
6. **Analytics**: Centralized Grafana dashboards, Prometheus metrics, and Langfuse tracing.
7. **Security**: Centralized METATRON security audits and firewalls.
8. **Knowledge System**: Shared Neo4j GraphRAG indices and Obsidian vaults.
