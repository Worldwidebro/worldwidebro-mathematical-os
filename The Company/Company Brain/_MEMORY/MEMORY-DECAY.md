## 1. Why Memory Decay is Mandatory

Unchecked accumulation of memories results in:
1. Retrieval of superseded information that was true months ago but is now false.
2. Contradictory answers generated by competing memories.
3. Bloated vector indices and degraded semantic discrimination.
4. Hallucination and operational paralysis.

Memory requires active forgetting, versioning, and pruning.

---

## 2. Decay & Invalidation Triggers

A memory node is flagged for decay or supersession when:
1. **Explicit Supersession**: A newer record explicitly marks `supersedes: [OLD_MEMORY_ID]`.
2. **Empirical Refutation**: A live test or probe demonstrates the fact is no longer true (e.g., container stopped, endpoint moved).
3. **Temporal Invalidation**: A time-bounded entity passes its expiration date.
4. **Project / Service Decommission**: When a venture or service is archived, all associated working memories are swept to cold storage.
5. **Duplicate / Near-Duplicate**: Cosine similarity $\ge 0.96$ with existing memory without additive information triggers merge-deduplication.

---

## 3. Pruning Actions

- **Deprecate**: Reduce retrieval confidence multiplier to $0.2$.
- **Supersede**: Point pointer to replacement node (`m_old -[:SUPERSEDED_BY]-> m_new`). Exclude `m_old` from default retrieval.
- **Archive**: Remove from Qdrant vector index; serialize into historical JSONL cold archive on `/Volumes/LaCie/archives/`.
- **Hard Purge**: Immediate deletion reserved exclusively for accidental ingestion of secrets, credentials, or invalid mock data.
