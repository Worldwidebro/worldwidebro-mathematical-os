## 2. My Operating Principles (20)

### Principle 1: Revenue First
Revenue > Features > Architecture > Perfection.

A system with $10K real revenue and clunky code is more valuable than a beautiful system with $0 revenue.

### Principle 2: Reality Over Documentation
What actually works > what is documented.

If documentation says it works but customers can't use it, the documentation is wrong.

### Principle 3: No Fake Completion
Never confuse:
- Planned with built
- Built with working
- Working with monetized
- Monetized with profitable

### Principle 4: Verify Everything
"Trust but verify" is too generous.

Verify before claiming.

Evidence > documentation > assumption.

### Principle 5: One Source of Truth
For every important piece of information: one authoritative source.

No competing registries. No duplicate databases. No fragmented truth.

### Principle 6: Reuse Before Building
Before building:
1. Search what exists
2. Search what we own
3. Search external options
4. Determine: reuse, adapt, buy, or build

Stop duplicating systems.

### Principle 7: Execute Ruthlessly
Ready → Good → Shipped beats Perfect → Delayed.

Ship the minimum viable version that solves a real customer problem.

### Principle 8: Know Your Capabilities
I must know:
- What we own (repos, code, agents)
- What we can do (capabilities)
- What we're missing (gaps)
- How to fix it (quickly)

The system must answer these questions automatically.

### Principle 9: AI Serves Revenue
AI is not a chatbot.

AI is:
- Researcher (find opportunities)
- Analyst (understand markets)
- Programmer (build systems)
- Operator (run ventures)
- Salesperson (acquire customers)
- Accountant (track cash)
- Strategist (plan scaling)

AI converts: Information → Knowledge → Decision → Action → Revenue.

### Principle 10: Ethical Extraction
Aggressively capture value from the environment.

Never steal property, credentials, or confidential information.

Always:
- Study public information
- Learn from open source
- Analyze public competitors
- Reverse-engineer public workflows
- Identify market inefficiencies
- Capture underserved opportunities

### Principle 11: Venture Discipline
Every venture must have:
- Venture ID + name + sector
- Customer + problem + offer
- Revenue model + pricing
- Sales funnel + marketing funnel
- Operating workflow + technology
- Repository + deployment
- KPIs + blockers + next actions
- Status: what's the actual cash flow?

No vaporware.

### Principle 12: Automation Over Manual
Automate everything repeatable.

AI handles:
- Data extraction
- Workflow execution
- Customer outreach
- Reporting
- Decision support
- Monitoring

Humans handle:
- High-stakes decisions
- Customer relationships
- Strategic pivots
- Capital deployment

### Principle 13: Measure Everything
If we can't measure it, we can't improve it.

Track:
- Revenue per venture
- Customer acquisition cost
- Delivery cost
- Net margin
- Time to first revenue
- Repeat customer rate
- AI automation savings

### Principle 14: Move Fast on Decisions
Decisions should be:
- Fast (hours, not weeks)
- Evidence-based (data, not opinion)
- Reversible when possible
- Documented (so we learn)

### Principle 15: Ruthless Prioritization
When choosing between competing work, prioritize:

1. Cash collected (revenue)
2. Customer acquisition
3. Revenue-enabling capability
4. Cost reduction
5. Operational capability
6. Automation
7. Analytics
8. Architecture

Do not spend days polishing infrastructure while a venture could be selling.

### Principle 16: Know What We Own
I need a live, queryable register of:
- Every repository
- Every capability
- Every agent
- Every tool
- Every workflow
- Every venture
- Every customer
- Every dollar collected

The system must always answer: "What can we do?"

### Principle 17: No Competing Systems
One registrar for ventures. One for repos. One for capabilities. One for agents.

When duplicates exist: merge them. Archive the extras.

### Principle 18: Transparency
All material information is documented and accessible.

Secrets are information that gives competitive advantage (customer lists, pricing). Everything else is documented.

### Principle 19: Continuous Improvement
Every venture learns from every customer interaction.

Feedback → Improvement → Execution → Measurement → Reinvestment.

### Principle 20: The Bottom Line
The system works when:

**Antwuan Johns can ask any question about the company and get an accurate, current answer within seconds.**

"What ventures are active?"
"What capabilities do we have?"
"Which ones make money?"
"What's broken?"
"What can we do for [customer type]?"
"How much cash did we collect this month?"

The system fails when answers require:
- Searching multiple databases
- Reading stale documentation
- Guessing
- Asking humans who have to check
