# Context-Aware Task Router Implementation Plan

## Overview

Implement a context-aware task routing system that combines:
- **Neo4j knowledge graph** (relational context: org structure, agent capabilities, execution history)
- **Qdrant vector store** (semantic context: similar tasks, outcomes, embeddings)
- **Capability engine** (dynamic resolution of required capabilities → best agents with history)
- **Enhanced router** (stateful routing with memory + graph-backed decisions)

Target: Integrate into existing vex-api as new layer. Reuse running Neo4j (7687) + Qdrant (6333) services.

## Phase 3: Capability Engine (Task 5)

**Task 5: Dynamic Capability Resolution + Agent Ranking**

Files:
- `vex-api/src/capability/engine.ts` (new)

Action:
- `get_required_capabilities(task_text)`: keyword match against known capabilities (for now, static list; future: LLM-based)
- `get_agents_for_capabilities(capabilities)`: Neo4j query
  ```cypher
  MATCH (a:Agent)-[:HAS_CAPABILITY]->(c:Capability)
  WHERE c.name IN $caps
  OPTIONAL MATCH (a)-[exec:EXECUTED]->(t:Task)
  RETURN a, avg(exec.success_rate) as avg_success
  ORDER BY avg_success DESC
  ```
- Return ranked agents with historical success rates

Verify:
- Query returns agents in order of success rate
- Test with sample capabilities

Done:
- Engine functions callable, return valid agent list

## Constraints Applied (Ponytail Mode)

1. **No new dependencies** for core routing logic (use existing neo4j, qdrant drivers already available)
2. **No abstractions** beyond immediate need (no factory patterns, no complex interfaces)
3. **Reuse existing infrastructure**: Neo4j/Qdrant already running, founder nodes already seeded, .env credentials ready
4. **Synchronous execution** (no queuing, no async orchestration layer—keep it simple for MVP)
5. **Minimal embedding model**: Use local small model (all-MiniLM or Ollama) to avoid external API dependency
6. **Graph stored as-is**: No complex materialized view, just straightforward Cypher queries

---

## Integration Points with vex-api

1. **Startup**: Call `seed_graph()` in index.ts startup (idempotent MERGE, safe to re-run)
2. **Neo4j driver**: Already initialized in `app.locals.neo4j` (reuse existing)
3. **New endpoint**: POST `/contextual-task` (parallel to existing `/founders`, `/ventures`, etc.)
4. **Task execution hook**: After any task completes (future: wire into workflow executor), call `history_recorder.record_execution()`
